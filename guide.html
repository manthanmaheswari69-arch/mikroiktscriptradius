ROUTEROS 7
PRACTICAL GUIDE

Build the network first,
then generate the script.

RouterForge makes a starting RouterOS script. It does not inspect your router, ISP design, existing firewall, or RADIUS server, so review every command before importing.

01

Safe workflow

Keep a way back into the router before changing access services.

  1. Record the WAN interface, customer-facing interface or bridge, address ranges, and existing bridges.
  2. Generate only the services you intend to run. Do not put Hotspot or PPPoE directly on a bridge port; select the bridge interface or a separate VLAN.
  3. Read the exported .rsc file and import it in a maintenance window. Use RouterOS Safe Mode for remote work and retain a current backup.
  4. Test one client, RADIUS authentication (if used), DNS, routing, and NAT before moving production subscribers.
02

PPPoE: authenticated subscriber sessions

Use PPPoE when each customer device should establish a PPP session with credentials.

RouterOS treats PPPoE as PPP carried over Ethernet. A normal server design uses an address pool, a PPP profile with the router’s local address and client pool, then a PPPoE server on the customer-facing Layer 2 interface. Avoid mixing ordinary DHCP or static addressing with PPPoE on that same customer interface unless you have deliberately designed the separation.

/ip pool add name=pppoe-pool ranges=10.10.10.2-10.10.10.254
/ppp profile add name=pppoe-profile local-address=10.10.10.1 remote-address=pppoe-pool
/interface pppoe-server server add interface=ether3 service-name=internet default-profile=pppoe-profile disabled=no

Add local /ppp secret records or enable RADIUS only after the RADIUS server, shared secret, and service choice have been tested. The official PPPoE documentation shows the same pool, profile, and server relationship.

03

Hotspot: captive-portal access

Use Hotspot when a client should be redirected to a login page before normal access.

A Hotspot server is attached to one Ethernet, wireless, VLAN, or bridge interface. It normally needs a gateway address, an address pool, DHCP, a Hotspot profile, and the server. RouterOS allows one Hotspot server per interface; when using a bridge, configure it on the bridge interface, not a member port.

/ip address add address=192.168.88.1/24 interface=bridge
/ip pool add name=hotspot-pool ranges=192.168.88.2-192.168.88.254
/ip dhcp-server add name=hotspot-dhcp interface=bridge address-pool=hotspot-pool disabled=no

Set a DNS name only when that name resolves to the Hotspot gateway as required by your portal design. Use HTTPS for a production login page and a valid certificate where possible. See MikroTik’s HotSpot documentation before customising portal files.

04

Static IP and MAC RADIUS access

Use this mode for clients with manually assigned addresses that authenticate by MAC address.

This tool configures a Hotspot profile with MAC login and RADIUS enabled, then creates a server and subnet without a DHCP server. Each device needs a unique static address in that subnet and a RADIUS record that matches the MAC format used by RouterOS. MAC authentication identifies a device; it is not equivalent to a user password, so protect the customer Layer 2 network and maintain an accurate device inventory.

/ip hotspot profile add name=mac-radius login-by=mac mac-auth-mode=mac-as-username-and-password use-radius=yes
/ip hotspot add name=ip-access interface=ether4 profile=mac-radius disabled=no

RouterOS can use RADIUS for Hotspot and PPP services; RADIUS attributes may override values in the local default profile. Confirm your RADIUS service type, shared secret, reachability, and accounting policy against the RouterOS RADIUS reference.

05

Troubleshooting and FAQ

Start with physical links and address design before changing generated commands.

Why will the script not generate?
The tool rejects missing required fields, invalid VLAN IDs, reused interfaces, and overlapping networks. Give each enabled service a separate non-overlapping subnet and interface or VLAN.
Why can a client authenticate but not browse?
Check the client’s gateway and DNS, the active default route, the RADIUS result, and the single generated source-NAT rule. Do not add broad NAT rules before understanding the existing firewall order.
Why does a Hotspot client not see the login page?
Confirm the client is on the intended interface and subnet, receives or has a valid address, and can reach the Hotspot gateway. Verify the DNS name and portal configuration separately.
Can I use the same port for PPPoE and Hotspot?
Not as a simple shared access network. Separate services with distinct interfaces, VLANs, or a tested network design; otherwise authentication and address handling can conflict.
Does the tool configure router security?
No. It creates selected service, routing, NAT, and related commands. Review input firewall rules, management access, DNS exposure, backups, updates, and RADIUS reachability for your environment.
